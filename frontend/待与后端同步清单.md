## 〇、user-service 认证对照（端口 `8001`）

基础路径：`/api/user` · 响应：`{ code, msg, data }` · 以 **`code === 200`** 判断成功

| 功能 | 方法 | 路径 | 请求体 / 鉴权 | 页面/调用 |
|------|------|------|---------------|-----------|
| 发注册验证码 | POST | `/api/user/sendRegEmailCode` | `{ email }` | Register |
| 注册 | POST | `/api/user/register` | `{ email, username, password, code }` | Register |
| 发登录验证码 | POST | `/api/user/sendLoginEmailCode` | `{ email }` | Login 验证码 Tab |
| 邮箱密码登录 | POST | `/api/user/login` | `{ email, password }` | Login 邮箱密码 |
| 用户名登录 | POST | `/api/user/loginByUsername` | `{ username, password }` | Login 用户名 |
| 验证码登录 | POST | `/api/user/loginByEmailCode` | `{ email, code }` | Login 验证码 |
| 用户信息 | GET | `/api/user/getUserInfo` | `Authorization: Bearer` | AuthBootstrap |
| 刷新 token | POST | `/api/user/refreshToken` | Header Bearer，**无 body** | `refreshToken()` 已封装，页面未自动调用 |
| 发重置验证码 | POST | `/api/user/sendResetEmailCode` | `{ email }` | ResetPassword |
| 重置密码 | POST | `/api/user/resetPwd` | `{ email, code, newPassword }` | ResetPassword |

**登录成功 `data`**：`userId`、`email`、`username`、`registerTime`、`token`、`refreshToken`  
**注册成功 `data`**：无 token，前端跳转 `/login`  
**错误**：`json.code !== 200` → `UserApiError`，页面展示 `msg`（含 400/401/422/503 等）

**Mock**：`.env.development` 中 `VITE_USE_MOCK=true` 时不请求后端（演示密码/验证码 `123456`）

**后端文档**：`backend/user-service/frontend-handoff.md`（一页纸）、`frontend-api.md`（全量）

## 〇·二、个人信息页 `/account`（user-service 扩展 · **待实现**）

> 页面：`src/pages/Account.tsx` · Hook：`src/hooks/useAccountPage.ts` · 封装：`src/lib/api/account.ts` · 类型：`src/types/account.ts`  
> 请求走 **axios**（`src/lib/api/client.ts`）：统一 loading 顶栏、401 跳转 `/login`、错误 `ApiClientError`。

基础路径：`/api/user` · 响应壳：`{ code, msg, data }` · **`code === 200`** 为成功 · 鉴权：`Authorization: Bearer <access_token>`

| 功能 | 方法 | 路径 | 请求体 / 说明 | 页面/调用 |
|------|------|------|---------------|-----------|
| 获取资料 | GET | `/api/user/profile` | 无 body | Account 进入时 |
| 更新资料 | PUT | `/api/user/update` | 见下表 `UpdateUserProfileDto` | Account 保存 |
| 学习统计 | GET | `/api/user/stats` | 无 body（`skipLoading: true`） | Account 进入时 |
| 注销账号 | DELETE | `/api/user/profile` | 无 body | **预留**，前端已封装未接 UI |

### 与现有接口的映射关系

| 新接口（Account 页） | 现有/相关接口 | 说明 |
|----------------------|---------------|------|
| `GET /api/user/profile` | `GET /api/user/getUserInfo` + 学习画像字段 | **建议后端合并**：账号字段来自 `getUserInfo`，`displayName/major/goal/level/updatedAt` 来自画像服务或 user 表扩展 |
| `PUT /api/user/update` | `PUT /api/profile`（`endpoints.ts` · 全站画像） | 字段重叠：`displayName` ↔ 画像 `name`；其余 `major/goal/level` 一致。可二选一实现或 profile 内部转发 update |
| `GET /api/user/stats` | `GET /api/analytics/overview`（规划中） | Account 仅需 4 个汇总数字；也可由 analytics 聚合后 user-service 代理 |
| `DELETE /api/user/profile` | 无 | 账号注销，需后端定义软删/硬删策略 |

### 请求 / 响应类型（TS：`src/types/account.ts`）

**GET `/api/user/profile` → `data: UserProfileDto`**

```json
{
  "userId": 1,
  "email": "learner@example.com",
  "username": "learner",
  "registerTime": "2026-01-15T08:00:00Z",
  "displayName": "张三",
  "major": "计算机科学",
  "goal": "掌握机器学习基础",
  "level": "中级",
  "updatedAt": "2026-05-20"
}
```

**PUT `/api/user/update` ← `UpdateUserProfileDto`（字段均可选）**

```json
{
  "displayName": "张三",
  "major": "计算机科学",
  "goal": "掌握机器学习基础",
  "level": "中级"
}
```

响应 `data` 同 `UserProfileDto`（含更新后的 `updatedAt`）。

**GET `/api/user/stats` → `data: UserStatsDto`**

```json
{
  "healthScore": 78,
  "goalProgress": 42,
  "pathProgress": 35,
  "sessionCount": 12
}
```

| 字段 | 含义 | 前端 Mock 来源 |
|------|------|----------------|
| `healthScore` | 画像健康度 0–100 | `store.profile.healthScore` |
| `goalProgress` | 目标完成度 % | `store.profile.goalProgress.percent` |
| `pathProgress` | 路径平均进度 % | `pathStages` 各 topic.progress 均值 |
| `sessionCount` | 历史会话数 | `store.sessions.length` |

### 前端 Fallback（后端未实现时）

| 场景 | 行为 |
|------|------|
| `VITE_USE_MOCK=true` | 不请求后端，直接用 `useAppStore` + `mockData` |
| 真实环境 + 接口 404/未实现 | `getUserProfile`：catch → `fetchUserInfo()` + store 画像合并 |
| 真实环境 + 更新失败 | `updateUserProfile`：catch → 仅更新本地 store（演示可保存） |
| 真实环境 + stats 失败 | `getUserStats`：catch → 从 store 计算 Mock 统计 |

联调完成后可去掉 catch fallback，改为直接抛错并在页面展示 `ApiClientError.message`。

### 后端实现建议（user-service）

1. **profile GET**：鉴权后读 user 表 + 画像表（或 JSON 扩展字段），组装 `UserProfileDto`。  
2. **update PUT**：校验字段长度/枚举，写画像表，返回完整 DTO。  
3. **stats GET**：只读聚合，避免 N+1；可与 learning-path / chat 服务 RPC 或读缓存。  
4. **delete DELETE**：预留；需确认 GDPR/软删、token 失效、关联数据清理。

**OpenAPI 登记**：在 `8001/docs` 增加上述 4 条，与 `frontend-handoff.md` 同步字段名（camelCase 与现有 `getUserInfo` 一致）。

## 〇·三、agent-service 双表 RAG（`knowledge_chunks` + `video_resources`）· **待队长接入**

> **现象**：用户问「Python 学习视频链接」时，回复为「知识库没有收录」——**不是前端未连通**，而是 **agent-service 检索代码未查 `video_resources` 表**。  
> **数据**：队长确认 PG 里 **`video_resources` 已有 B 站数据**（`embedding vector(512)`、索引已建）。  
> **代码**：全仓库 **0 处** 引用 `video_resources`；`chat_service.search_knowledge` 仅查 `knowledge_chunks WHERE collection='runoob'`。

### 当前 vs 应有

| 表 | 内容 | agent-service 是否检索 |
|----|------|------------------------|
| `knowledge_chunks` | 菜鸟教程文字切片（runoob） | ✅ 已检索 top-5 |
| `video_resources` | B 站教程视频（title/url/bvid/播放量等） | ❌ **未接入** |

前端 **`POST /api/agent/chat`** 不变：仍 `{ user_input, session_id }` → `{ ai_reply: Markdown }`。  
后端接入视频 RAG 后，**无需改前端请求体**；`MarkdownContent` 已支持外链新窗口打开。

### 建议后端改动（`backend/agent-service/services/chat_service.py`）

1. **新增** `search_videos(query_vec)`（与 `search_knowledge` 同库、同 BGE 512 维）：

```sql
SELECT title, url, author, play_count, duration_seconds,
       category, sub_module, content
FROM video_resources
ORDER BY embedding <=> %s::vector
LIMIT 3;
```

2. **`get_knowledge_reply` 流程**（二选一，队长定）：
   - **并行双检索**：runoob top-5 + video top-3，拼进 system prompt 两段上下文；或
   - **意图分流**：用户句含「视频/链接/B站/教程推荐」时优先/仅查 `video_resources`。

3. **`build_context` 扩展**：视频块格式示例，便于模型直接输出 Markdown 链接：

```text
[视频1] 《{title}》· {author} · 播放 {play_count}
链接：{url}
分类：{category} / {sub_module}
```

4. **`core/prompts.py`**：当上下文含 `[视频N]` 时，**必须在回答中列出 `url`**（Markdown `[标题](url)`），禁止再说「知识库没有视频」。

### `video_resources` 字段（与队长表结构一致）

| 字段 | 用途 |
|------|------|
| `bvid` / `url` | 唯一视频与跳转链接 |
| `title` / `description` / `content` | 展示与向量检索文本 |
| `category` / `sub_module` | 与 runoob 12 分类对齐，可做筛选 |
| `embedding` | `vector(512)` cosine，模型 **BAAI/bge-small-zh-v1.5**（与 runoob 入库一致） |
