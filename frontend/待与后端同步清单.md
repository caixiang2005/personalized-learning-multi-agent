## 一、需要和 backend 对齐的内容（给后端同学）

联调前请后端确认并提供：

| 序号 | 内容 | 说明 |
|------|------|------|
| 1 | API 根地址与端口 | 如 `http://localhost:8080`，前端用 Vite 代理 `/api` |
| 2 | 登录方式 | 邮箱密码 / 验证码 / 用户名密码 是否都支持 |
| 3 | Token 格式 | JWT 放 Header `Authorization: Bearer xxx` 是否一致 |
| 4 | 统一错误体 | 如 `{ message: string, code?: number }` |
| 5 | 流式对话协议 | SSE 每行 JSON 结构（见下文「对话 SSE」） |
| 6 | 学习画像字段 | 是否与 `src/types/index.ts` 中 `LearningProfile` 一致（≥6 维度） |
| 7 | 资源类型枚举 | `document \| mindmap \| exercise \| video \| practice` |
| 8 | 资源状态枚举 | `todo \| learning \| done \| mastered \| favorite` |
| 9 | OpenAPI 或接口文档 | 便于前端改 `types` 与 `client.ts` |

详细路径见 **[BACKEND_INTEGRATION.md](./BACKEND_INTEGRATION.md)**。

## 三、按页面：进入页面时要拉什么数据

| 页面 | 进入时建议请求 | 用户操作时建议请求 |
|------|----------------|-------------------|
| Login | 无 | 登录 / 发验证码 |
| Home | 可选 GET profile | 提交背景 → 生成路径/画像 |
| Chat | GET sessions；选中会话 GET messages | 发消息 → stream；上传；反馈 |
| Profile | GET profile | POST patch 更新画像 |
| Path | GET learning-path | PUT resource-status |
| Resource/:id | GET resources/:id | 无（导出若需要另议） |
| Exercise/:id | GET exercises/:id | POST submit |
| Analytics | GET overview + weak-points + suggestions | 切换时间 range 重新 GET |
| Settings | GET profile 或 user/me | POST logout |

## 四、对话 SSE 建议格式（需与后端统一）

前端已按此结构在 `client.ts` → `streamChat` 中解析：

```text
data: {"type":"text","content":"一段文字"}
data: {"type":"resource","resource":{ "id","type","title",... },"progress":50}
data: {"type":"done"}
data: {"type":"error","content":"错误说明"}
```
